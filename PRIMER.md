# cpsolver2 — Project Primer

Complete TUI redesign of my earlier [`crossplay-solver`](https://github.com/OneTrueJASH/crossplay-solver).

The workspace has two crates. `crates/ravyn` is the engine (RAVYN, MIT): rules, tiles, board, dictionary, leaves, move generation, simulation, inference, endgame and pre-endgame. It also builds the `ravyn` command-line tool (`crates/ravyn/src/bin/ravyn.rs`: `gen`, `sim`, `endgame`, `preendgame`, `infer` on CGP positions, `gcg` on game records; standard library only, tested as a process in `tests/cli.rs`). The root package is the app (MIT): its library (`src/lib.rs`) re-exports the engine's modules at their old paths and adds the TUI; the `cpsolver2` binary (`src/main.rs`) is the terminal setup, a small CLI (`--help`, `--version`, `--data-dir`, `--game`, `--list`), the panic hook, the quit-on-signal flag (SIGHUP, SIGTERM, SIGINT via `signal-hook`) and the event loop. `ui::frame::draw_ui` draws a frame from the `App`.

## Module Layout

| Module | Purpose |
|---|---|
| `rules` | `Rules`: premium layout, start square, letter values, tile distribution, bingo bonus and `Ending` (`EqualTurn` for Crossplay; `GoOut` for Scrabble: going out gains twice the opponent's rack, six scoreless turns charge each side its own); every `Board` carries `&'static Rules`; presets `CROSSPLAY` and `SCRABBLE` |
| `tile` | `Tile` struct, `Rack` (7-slot); point values come from the rules (`Rules::tile_value`); constants: `RACK_SIZE` |
| `board` | 15x15 `Board` with its rules (`Board::new()` is Crossplay, `Board::with_rules`), `Cell`, `Premium` enum, `Direction` enum; constants: `BOARD_SIZE` |
| `dictionary` | FST-backed `Dictionary` (word validation) plus the same words flattened at load time into a DAWG array (`DawgNode`, `DawgArc`: each node's arcs contiguous and sorted) that the move generator walks with `root()`, `child()` and `arcs()`, `leave_value()` (fitted table or heuristic, phase-scaled, corrected to the bingo bonus set by `for_rules`); the app's `dictionary` module adds `load_default_dictionary()`, which also attaches the leave table when `data/leaves.rlv` is present |
| `leaves` | `LeaveValues` — a trained table (`RLV2`: the bag it was trained with, then one i16 hundredth-of-a-point value per leave of 1–6 tiles in `all_leave_keys` order), `leave_key()`; `bingo_probability()` / `bingo_bonus_correction()` — self-play-fitted logistic model that converts values fitted under one bingo bonus to another (e.g. the Crossplay table under Scrabble's 50) |
| `leavegen` | `train_generation()`: one generation of leave training: greedy self-play with the current values; each leave kept with 14+ tiles in the bag is a sample whose target is the next turn's score plus the next leave's value (TD(0)), centred on the empty leave; a ridge regression on singles, pairs and size × vowels gives a smooth model, and each leave shrinks from it toward its own mean by n/(n+20) |
| `game` | `SolverState` (Board + Rack), `unseen_tiles()` (from the board's rules), `bag_size()`, endgame detection, `from_cgp()`, `get_suggestions()` (plays plus exchanges when the bag allows), `exchange_moves()`, `best_exchange()` / `top_exchanges()` (only the winners are built, from the subset leave table), `observed_move_loss()` (equity an observed opponent play gave up, over sampled completions of their rack) |
| `inference` | `infer_leave()`: what the opponent kept, from their play: every leave is tried, kept if the play was within `equity_margin` (5) of that rack's best play or exchange, and weighted by draw count; `RackInference` (played tiles, top leaves, `LetterMarginal` per-letter expected counts and P(at least one)). The board is analyzed once (`Solver::prepared`), each rack's search stops at the first play beating the cutoff (`Solver::any_play_beats`), and leaves are checked in parallel. Checked against RefEngine's recorded answers in `crates/ravyn/tests/reference_movegen.rs` |
| `solver` | `Move` with `MoveKind` (`Play` / `Exchange` / `Pass`), `coords()` (`8D`/`D8`, `-` for non-plays), anchor-based move generation over the DAWG with bitmask cross-checks and incremental scoring; besides the full list (`find_moves`), allocation-free searches keep only what playouts need (`best_move_by_score`, `best_score`, `best_move_by_equity`, `top_moves_by_equity`, `any_play_beats`) and build only the winners; `prepared()` analyzes the board once for many racks, and `analysis()` / `with_analysis()` / `BoardAnalysis::after_placing()` reuse an analysis and update it after a move (only the placed squares and the run ends around them are recomputed); the best-play searches bound each anchor first (rack's highest values on the most multiplied squares of every reachable span, plus the best leave of the matching size) and search anchors best-first, stopping when no remaining bound can change the answer (1.2-2.5x on playouts and simulation); ties between equal plays follow one canonical order (score, longer word, then position and spelling), so every search and the full list agree; `LeaveTable` holds the leave value of every sub-multiset of the rack (at most 128) indexed by a mixed-radix subset index, `leave_value_with_phase()` (per-letter fallback), `Solver`; constants: `EXCHANGE_MIN_BAG` (7), `PASS_WORD`. Verified play-for-play against RefEngine's recorded answers on 32 positions (`crates/ravyn/tests/reference_movegen.rs`) |
| `stats` | `GameStats`, `GamePhase`, `TileLocation`, power tile tracking, rack analysis |
| `games` | Saved games: `SavedGame` (`name`, `cgp`, `updated`, `opp_losses`: `OppLosses`) stored as `<slug>.toml` in `default_dir()` (`<data dir>/cpsolver2/games`, `None` under `cfg(test)`; every function takes the directory), atomic `save()`, `load()`, `list()` (`GameEntry`: score, bag, locked; newest first), `slug()`, per-game `<slug>.lock` files holding the pid (`lock()` refuses a live holder and takes over stale ones, `lock_holder()`, `unlock()`), `untitled_name()`, `unused_name()`, `relative_time()`, and `migrate_session()` (imports an old-style `session.cgp`, whenever one appears, as "Restored session") |
| `settings` | `Settings` with `DisplaySettings` (`default_sort`, `sidebar_visible`), TOML persistence at `~/.config/cpsolver2/settings.toml` (`#[serde(default)]`, atomic temp-file + rename writes, an unparsable file moved to `settings.toml.bak` by `load_or_recover`); constant: `LEXICON = "AMERICAN"` |
| `logging` | Per-process log `cpsolver2-<pid>.log` in the state dir (cache dir on macOS) under `cpsolver2/`, created 0600 with `O_NOFOLLOW`, pruned at startup (older than 7 days, at most 20 kept); in-memory ring buffer (`RING_CAPACITY` lines) read by the log viewer; `start_section()` begins a new viewer section on each solve |
| `datafiles` | Data-file locations (`data/words.fst`, `data/leaves.rlv`), data-root search (`--data-dir`, `$CPSOLVER_DATA_DIR`, user data dir, `<exe>/../share/cpsolver2`, working directory), Git LFS pointer-stub detection (`is_lfs_pointer`, `file_status`), the startup warning when the leave table is a pointer (`lfs_warning`), and the test helpers (`test_data`, including `app_lock`, which runs app tests with background work one at a time) that make data-dependent tests skip cleanly and run from any working directory |
| `mcts` | Split into `pool` (unseen pool, position fingerprints, per-iteration seeds), `opponent` (`OpponentModel`), `playout` (one simulated game), `eval` (fixed-budget evaluator), `selfplay` (engine matches) and the test-only `studies`. `MctsEvaluator`, `MctsResult`, `MctsConfig` (`for_bag`), `TilePool`, `TracePoint` — Monte Carlo playouts under Crossplay rules for every phase with the bag non-empty: greedy static-equity play (including exchanges) until the bag empties, then exact 2-ply last turn and score-only final move; cut-off positions valued as spread + leaves + tempo (±21); win probability from a normal model with sd² = 150 + 79.8 × bag (`study_win_model` found neither a logistic fit on bag, unseen blanks and S's nor a per-bag tempo better on held-out games, so the normal model and the constant tempo ±21 stand); in the greedy phase with 1–6 tiles in the bag a player may pass when keeping the whole rack beats every play (never twice in a row); common random numbers across candidates (playout *i* uses its own generator seeded from the position fingerprint and *i*, the same for every candidate; the deal is laid out `[opponent rack | bag]` with our draw off the top of the bag, so every candidate faces the same opponent rack; exchange returns are reshuffled with the iteration's own generator), paired-difference pruning, wall-clock budget, Rayon parallelism over (candidate, batch of 8 playouts) jobs so every core stays busy when few candidates remain. `OpponentModel` biases the opponent's dealt rack with inference marginals and weakens their simulated play to a measured softmax temperature (see key behavior 12). Also hosts the self-play studies (`study_spread_variance`, `study_bingo_probability`, `study_loss_calibration`, `study_win_model`, ignored tests) that produced those constants, and the engine-versus-engine harness (`self_play_match`, `MatchEngine`, `SimChoice`) driven by `examples/selfplay.rs` |
| `sim` | `Simulation`: anytime simulation of every candidate (arms = plays, exchanges, pass). Admission order: exchanges and pass, then plays by static equity, in batches of 256 (widening); every arm gets `min_playouts` (n₀), then racing: an arm keeps being sampled while the upper confidence bound (z = 2.5) of its paired difference to the leader on spread *or* on win rate reaches +ε (`SPREAD_EPSILON` 0.5, `WIN_EPSILON` 0.005); once settled the top 5 on each metric keep being refined until the budget ends. Jobs of 8 playouts run on the rayon pool as a continuous pipeline (`JOBS_PER_THREAD` in flight per thread, results applied in iteration order per arm, racing bounds refreshed every 2 ms). `ArmStats` (Welford mean/variance for spread and win, bingo counts, per-iteration values), `SimSnapshot` (published about every 300 ms), `SimState` (saved for resume, keyed by `sim_key`: position fingerprint, candidates, opponent model, plies, score difference) |
| `endgame` | `EndgameSolver`, `EndgameMove`, `PvMove`, `PASS_WORD` — Crossplay-native endgame solver: exact 2-ply (including passing) when the opponent replies, score-only when our move ends the game; `best_value()` gives just the best value, trying plays by falling score and stopping when one cannot beat it (a final reply scores at least 0) |
| `negamax` | `solve_go_out()`: exact endgames under the go-out ending: negamax with alpha-beta, principal variation search, a transposition table (the best move itself kept per position and tried before any other move is generated), iterative deepening within `GoOutSettings`, and frontier nodes (one ply from the limit) answered by one bounded search (`Solver::best_endgame_play`); exact when a depth finishes without its limit, else an estimate; root moves cut off by the best carry upper bounds. Parallel at the root: the previous depth's best move is searched first, then the rest across all threads with a shared atomic alpha and a transposition table in 64 locked shards; a move above the alpha it started with is exact, otherwise a bound, so a solved answer does not depend on thread timing (an estimate, at a depth that hit its limit, can vary between runs) |
| `preendgame` | `solve_one_in_bag()`: with one tile in the bag, every play against each possible last tile (weighted by copies), each case solved exactly with perfect information (`EndgameSolver::best_value` for the opponent's turn and our final play). Plays are first capped (the opponent can at least take their top-scoring play or pass), then solved from the highest cap (win probability, then expected spread) until no cap can beat the best exact result; unsolved plays keep `exact: false`. The pass is always solved (`pass_value`): the opponent's replies are capped (after each we can at least pass or take our top-scoring play, then they play last) and solved best-first; their passing back counts as ending the game (0), which can only understate the pass. `solve_two_in_bag()`: two tiles in the bag. A play of two or more tiles draws both (one case per pair, `EndgameSolver::best_value_with` on the board's analysis); a one-tile play draws one and leaves the opponent the `pass_value` position (one case per order the two come out). One-tile caps are tightened by valuing the opponent's top-scoring reply exactly; the most promising play is solved first, then each play's cases likeliest first, with caps standing in for the rest, giving the play up once that mix can't beat the best; a per-play `ReplyCache` shares the opponent's replies across cases (a reply's value depends on the racks after it, not on the tile left in the bag). Passing is not evaluated. Both solvers share `solve_from_caps` (seeding, per-case abandonment, deadline); with one tile the pass is solved first, its eight cases sharing a `ReplyCache`. A deadline stops solving plays (never capping, nor the pass); `proven()` says whether the top play is certain. `EndgameSolver::best_value_with` fetches replies by score in rounds (`Solver::top_moves_by_score`). `PreEndgameMove` (win, spread, `DrawOutcome` per bag content) |
| `app` | Split into `state`, `input`, `engine`, `opponent`, `edit`, `session` and `sort` (see the module docs). `session` is the open game: throttled autosave (`autosave_if_due`, `AUTOSAVE_INTERVAL`), its lock, `open_game` / `new_game` (which save and release the old game and clear its undo history, inference and simulation cache), Save As / rename / delete, the picker keys and the quit flow (`request_quit`: untitled games are offered a name). `App` (central state), `Focus`, `SortMode`, `FinalTurn` (who plays the last move once the bag is empty), `SimResult` (display record for playout/endgame results), `DialogState`, `BoardTab`, `handle_key()`/`handle_mouse()` event handlers, undo support, engine routing by game phase, background rack inference (`ravyn::inference`), opponent-strength measurement (`opp_temperature()`, `opp_error_estimate()`) |

## Key Design Differences from crossplay-solver

1. **Mouse support** — thread-local hit map populated during render, resolved on click
2. **Centralized theme** — all colors in `ui::theme`, no inline `Color::Rgb(...)` in widgets
3. **Fluid layout** — `AppLayout::compute()` replaces the 4-mode `LayoutMode` enum
4. **Event handlers in App** — `handle_key()`, `handle_mouse()`, `handle_paste()` methods on `App` (in `app::input`), so key and click scripts can drive the app in tests
5. **Shared popup frame** — `popup_frame::render_popup_frame()` used by all dialogs
6. **Clean event loop** — main loop dispatches `Event::Key` / `Event::Mouse` to `App`, which returns `AppAction`
7. **Settings auto-persisted via keybindings** — no settings dialog; sort mode and sidebar visibility are saved on toggle
8. **Native endgame solver** — `endgame.rs` implements Crossplay-specific 2-ply endgame (equal turn rule, no tile penalties)
9. **Engine routing by phase** — `App::run_mcts_evaluation`: our move ends the game → sort by score; bag empty and the opponent replies → `EndgameSolver`; one tile in the bag (and a full opponent rack) → `ravyn::preendgame::solve_one_in_bag`, exact over every possible last tile; two tiles → `solve_two_in_bag`; both within the simulation budget, saying whether the best is proven; otherwise native playouts (`mcts.rs`) with depth by bag size (2 plies with 22+ in the bag, 4 with 8–21, to the end with 2–7). The endgame and pre-endgame share one job (`App::exact_job`, an `ExactOutcome` of moves, results and a summary built on the worker thread). Every engine applies Crossplay's ending
10. **Leave values trained by self-play** — `data/leaves.rlv` was fitted by `ravyn train-leaves` on Crossplay's rules (40-point bingo, 3 blanks): three generations of 500,000 greedy self-play games, the first playing with the per-letter heuristic and each later one with the previous values. Over 20,000 paired self-play games the third generation beat RefEngine's `AMERICAN.klv2` (fitted for Scrabble and corrected to Crossplay) by 2.08 ± 0.95 points of spread per game (score 0.509 ± 0.006), and the heuristic by 16.3 ± 2.4. With both sides choosing moves by simulation (`ravyn match --sim 5,16`, 4,600 games) the gain over RefEngine's table held: 2.23 ± 2.02 points (score 0.513 ± 0.013). Falls back to the per-letter heuristic in `solver.rs` (scaled the same way) when the file is missing. Leave weight is scaled by phase (`PhaseScaling::Smoothed`, the default): 1.0 down to 21 unseen tiles, then linear to 0.6 at 14 and 0.25 at 7, flat below. It replaced the stepped 1.0 / 0.6 / 0.25 after self-play: +0.49 ± 0.33 and +0.48 ± 0.27 points of spread per game over 4,000 and 6,000 paired games
11. **Exchanges** — offered and played out whenever the bag holds at least `EXCHANGE_MIN_BAG` (7) tiles; the threshold is the common word-game convention and has not been confirmed from NYT's own rules text
12. **Opponent model in playouts** — `OpponentModel` (`mcts/opponent.rs`) feeds two measured facts into the playouts. (a) Rack inference (`ravyn::inference`, run on the board before the opponent's move, given the tiles they played with a blank as `?`, the move's score, and our rack as tiles they cannot hold) gives per-letter marginals (expected count of each letter among the tiles the opponent kept after their last play); the playout deal samples their kept tiles by weight (inferred expectation over the uniform expectation, clamped to [0.05, 20]) so inferred tiles land in their rack, never in our draw. The evaluation thread waits up to 3 s for a fresh inference and otherwise uses the stored one, which stays valid until the opponent moves again. (b) Every auto-scored opponent move is measured against the best play/exchange from 10 sampled completions of their rack (`observed_move_loss` in `game.rs`); the running mean maps to a softmax temperature for the simulated opponent through a fitted inversion (`study_loss_calibration`: measured ≈ 7.78 + 0.557·τ — the baseline exists because a sampled completion usually admits a better play than their true rack), shrunk by n/(n+2) and capped at 12. Temperature affects only the opponent's greedy-phase moves; both players stay exact on the final two turns, and our own side is always greedy

## Background work

Evaluations (playouts, endgame search) and inference run on worker threads (`spawn_worker`, which catches panics; the panic hook logs worker panics instead of printing over the TUI). Every evaluation is a `Job` carrying the `position_stamp` it was started under and a cancel flag (`Arc<AtomicBool>`, checked per playout and per endgame move). Any change to the position (board or rack edit, apply, undo, reset, score edit, Ctrl+E, re-solve) bumps the stamp and cancels the job, and a result whose stamp no longer matches is dropped. The board snapshot used to detect the opponent's next move (`last_applied_board`) is taken when an evaluation starts, never from a result. A solve that finds no new tiles after our move means the opponent passed or exchanged, which clears the stored inference.

## Event loop

The main loop draws only when something changed (an input event, a result or inference arriving, or the spinner while an evaluation runs), and handles every pending event before drawing again. A loading frame is drawn while the saved games are read. Each iteration autosaves the game when it changed (any `position_changed`, at most once per `AUTOSAVE_INTERVAL`; the poll timeout shrinks to wake up for it) and checks the signal flag; on the way out (quit, signal, or a draw/read error after the terminal went away) `App::shutdown` saves the game and releases its lock. Bracketed paste is on: pasted CGP loads a position, and a pasted GCG game record is imported (`app::record`). OSC 52 writes the clipboard (`App::pending_clipboard`). Solving stays on the UI thread: `find_moves` with the opponent-loss measurement takes at most about 44 ms, even with two blanks (BEECH ??EINRS, 40,559 moves).

## Settings

Settings are stored in `~/.config/cpsolver2/settings.toml` and auto-persisted when changed via keybindings or a sort-tab click (no settings dialog). Tests never touch the file (`config_path()` is `None` under `cfg(test)`).

The `Settings` struct contains only `DisplaySettings`:
- `default_sort` — default sort mode for suggestions (`Equity`, `Mcts`, `Score`, `Leave`, `Length`, `Alpha`)
- `sidebar_visible` — whether the sidebar is shown by default

## Data

- `data/leaves.rlv` — the trained leave table (1.8 MB). Nothing from RefEngine remains but its move generation on reference positions, recorded as test fixtures (`crates/ravyn/tests/fixtures/`)
- `data/words.fst` — FST dictionary used by the native move generator

## Crossplay-Specific Rules

- 100 tiles (3 blanks, 5 S's)
- 40-point bingo bonus (not 50)
- Unique premium square layout (not standard Scrabble), letter values and tile distribution: `ravyn::rules::CROSSPLAY`
- Endgame: when a player draws the last tile from the bag, the *other* player gets one last turn and then the player who emptied the bag plays the final move (equal turn rule). The game then ends even if both still hold tiles
- No leftover tile penalty — unplayed rack tiles don't affect scoring
- No go-out bonus — emptying your rack gives no extra points
- A turn may also be used to pass, or to exchange any number of tiles (the turn is forfeited; assumed to require at least 7 tiles in the bag)
- Consequence for the solver: with the bag empty, the opponent only replies to our play if *they* emptied the bag. `App.final_turn` tracks this (inferred from moves applied through the app; Ctrl+E overrides it for hand-entered positions; the stats pane shows `Final move: opponent?` while it is only assumed)
